# CSS 审计与结构整理

## 当前结构

`src/styles/app.css` 按基础、首页海报、导航、令牌与徽章、规则、人数、角色弹窗、流程、剧本速查表、语言切换组织。每个组件的基础规则及其媒体查询放在同一区域。

同一媒体条件下，一个选择器只定义一次；不同断点、语言和交互状态的覆盖属于显式差异，予以保留。不再通过在文件末尾追加一层修补规则调整现有组件。

## 本轮清理

- 从浏览器实际解析结果和最终模板逐条核对，删除孤立声明、空值、无用选择器和未引用的主题变量。
- 405 条有效样式规则收敛为 350 条；合并同条件重复选择器，清除被后续简写覆盖的冗余属性。
- 删除没有页面生产者的 `.card`、`h3`、无效表格单元格选择器及流程中的不匹配选择器。
- 解决基础规则和不同断点之间的历史覆盖，保留清理前的实际尺寸与外观。
- 流程提示使用组件范围选择器表达优先级，移除强制覆盖。仅保留打印时隐藏导航的 `!important`。
- 保留原中英文海报。通过 CSS 隐藏海报底部画出的按钮，首页共用全站导航。
- 保留手机尺寸、英文长角色名、短屏幕、打印、hover、reduced-motion 等明确场景。

## 验证与防回归

- `npm test` 包含 CSS 结构检查：完整括号与声明结构、无孤立声明、无空值、无同条件重复选择器、无同块重复属性。
- `CSS_AUDIT=1 npm run test:browser` 额外输出 CSS 使用记录、计算样式快照及截图；要求所有选择器在采样页面/状态中找到匹配元素。
- 使用 Chrome 独立临时配置核对中英文、三个剧本全部角色弹窗、两套流程全部阶段。
- 对比 320、350、360、380、390、430、560、768、1280 像素宽度下五个页面，共 90 组布局、字体、颜色等计算样式，清理前后无差异。
- 截图比较中 84/90 张文件完全一致；像素抽查的非一致处位于滚动条及少量边缘像素，未观察到内容布局变化。
- 构建和既有交互检查通过。真机触控、打印实物及不同浏览器仍可继续人工审核；选择器覆盖记录不是所有设备环境的穷尽证明。

PowerShell 审计命令：

```powershell
$env:CSS_AUDIT='1'
npm run test:browser
```

后续改样式请在对应组件和断点内修改，不要重新追加同条件覆盖。新增组件、媒体条件或交互状态时，也需要更新检查范围。
